- Terraform outputs
- Terraform state

# 1. Terraform Provider

The AWS provider allows Terraform to communicate with AWS.

Example `provider.tf`:

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }

  required_version = ">= 1.5.0"
}

provider "aws" {
  region = var.aws_region
}
```

The provider tells Terraform which cloud platform should be used.

---

# 2. Variables

Variables make Terraform configurations reusable and easier to modify.

Example `variables.tf`:

```hcl
variable "aws_region" {
  description = "AWS region where the S3 bucket will be created"
  type        = string
  default     = "ap-south-1"
}

variable "bucket_name" {
  description = "Globally unique S3 bucket name"
  type        = string
}
```

The bucket name must be globally unique within Amazon S3.

---

# 3. Terraform Variables File

Example `terraform.tfvars`:

```hcl
aws_region  = "ap-south-1"
bucket_name = "my-terraform-s3-demo-unique-name"
```

Replace the bucket name with a globally unique name before running Terraform.

---

# 4. S3 Resource

Example `main.tf`:

```hcl
resource "aws_s3_bucket" "demo" {
  bucket = var.bucket_name

  tags = {
    Name        = "Terraform S3 Demo"
    Environment = "Learning"
  }
}
```

This resource instructs Terraform to create an S3 bucket.

---

# 5. Outputs

Example `outputs.tf`:

```hcl
output "s3_bucket_name" {
  description = "Name of the S3 bucket"
  value       = aws_s3_bucket.demo.bucket
}

output "s3_bucket_arn" {
  description = "ARN of the S3 bucket"
  value       = aws_s3_bucket.demo.arn
}
```

Outputs make useful resource information available after Terraform operations.

# 8. `terraform validate`

Validate the Terraform configuration:

```bash
terraform validate
```

Expected output:

```text
Success! The configuration is valid.
```

This checks whether the configuration is syntactically valid and internally consistent.

# 9. `terraform plan`

Create an execution plan:

```bash
terraform plan
```

Terraform compares the desired configuration with the current state and determines what changes are required.

Example:

```text

```

The plan should be reviewed before applying changes.

# 14. Terraform State

Terraform maintains a state file called:

```text
terraform.tfstate
```

The state file keeps track of the infrastructure Terraform manages.

For example:

```text
Terraform Configuration
        |
        v
   Desired State
        |
        v
    AWS Resource
        ^
        |
terraform.tfstate
```

Terraform uses the state to determine what resources already exist and what changes are required.

## Important

Do not commit the following files to Git:

```text
terraform.tfstate
terraform.tfstate.backup
.terraform/
```

Add them to `.gitignore`:

```gitignore
.terraform/
*.tfstate
*.tfstate.*
*.tfvars
```

If `terraform.tfvars` contains only non-sensitive learning values, it may be committed if desired, but sensitive credentials and secrets should never be stored in Git.

# 01. IAM - Governance

## What is IAM?

**AWS Identity and Access Management (IAM)** is used to control authentication and authorization for AWS resources.

IAM determines:

- Who can access AWS
- What resources they can access
- Which actions they can perform

---

## IAM Users

An IAM user represents an identity that can interact with AWS.

A user can have:

- Username
- Credentials
- Permissions
- Access keys
- Console access

For example:

```text
Developer
    |
    v
IAM User
    |
    v
AWS Resources
```

---

## IAM Groups

Groups allow permissions to be assigned to multiple users.

Example:

```text
Developers Group
      |
      +---- User 1
      |
      +---- User 2
      |
      +---- User 3
```

A policy can be attached to the group rather than configuring permissions separately for every user.

---

## IAM Roles

An IAM role provides permissions that can be assumed by trusted entities.

Roles are commonly used by:

- EC2
- Lambda
- ECS
- Kubernetes workloads
- Other AWS services
- Federated users

For example:

```text
EC2 Instance
      |
      v
IAM Role
      |
      v
S3 Permissions
```

This avoids putting long-term AWS access keys directly inside an EC2 instance.

---

## IAM Policies

Policies define what actions are allowed or denied.

Example:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "*"
    }
  ]
}
```

Policies can control:

- Actions
- Resources
- Conditions
- Allow/Deny behavior

---

## Permissions

Permissions determine what an identity can do.

For example:

```text
s3:GetObject
s3:PutObject
s3:DeleteObject
```

A user with only `s3:GetObject` permission cannot automatically upload or delete objects.

---

## Principle of Least Privilege

Least privilege means giving an identity only the permissions required to perform its job.

For example, an application that only needs to read S3 objects should not receive unrestricted S3 administrator permissions.

Instead of:

```text
AdministratorAccess
```

use narrowly scoped permissions such as:

```text
s3:GetObject
```

for the required bucket or objects.

---

## IAM Best Practices

Important practices include:

- Follow least privilege.
- Use IAM roles for AWS workloads.
- Avoid sharing credentials.
- Enable MFA where appropriate.
- Avoid using the root account for everyday tasks.
- Regularly review permissions.
- Remove unused credentials.
- Avoid hardcoding access keys.
- Use temporary credentials where possible.
- Monitor and audit access.

---

## Common IAM Use Cases

IAM is commonly used for:

- User management
- Application permissions
- EC2 access to AWS services
- CI/CD pipelines
- Cross-account access
- Developer access
- Service-to-service authorization

# 02. EC2 - Compute

## What is EC2?

**Amazon Elastic Compute Cloud (EC2)** provides resizable virtual servers in AWS.

An EC2 instance can run:

- Linux
- Windows
- Web servers
- Applications
- APIs
- Databases
- Development environments

---

# AMI

An **Amazon Machine Image (AMI)** is a template used to launch an EC2 instance.

An AMI contains information required to create an instance, such as:

- Operating system
- Software
- Configuration
- Root volume information

Example:

```text
AMI
 |
 +---- Operating System
 |
 +---- Software
 |
 +---- Configuration
 |
 v
EC2 Instance
```

---

# Instance Types

EC2 provides different instance families for different workloads.

Examples include:

- General purpose
- Compute optimized
- Memory optimized
- Storage optimized
- Accelerated computing

The appropriate instance type depends on:

- CPU requirement
- Memory requirement
- Network performance
- Storage requirement
- Cost

---

# Key Pairs

Key pairs are used for secure access to EC2 instances.

For Linux instances, an SSH key pair can be used to authenticate.

Example:

```bash
ssh -i key.pem ec2-user@<public-ip>
```

Private keys should be protected and should never be committed to Git.

---

# Security Groups

A Security Group acts as a virtual firewall for an EC2 instance.

Example rules:

```text
HTTP    80
HTTPS   443
SSH     22
```

Security Groups control inbound and outbound traffic.

---

# EBS

**Elastic Block Store (EBS)** provides persistent block storage for EC2 instances.

It can be used for:

- Operating system disks
- Application storage
- Databases
- Persistent files

---

# Public vs Private IP

### Public IP

A public IP allows communication with the internet when the network configuration permits it.

### Private IP

A private IP is used for communication within the VPC and connected networks.

Example:

```text
Internet
    |
Public IP
    |
EC2
    |
Private IP
    |
VPC Network
```

---

# EC2 Instance Lifecycle

Common states include:

```text
Pending
   |
   v
Running
   |
   +----> Stopping
   |          |
   |          v
   |       Stopped
   |
   +----> Terminating
              |
              v
           Terminated
```

---

# Common EC2 Use Cases

EC2 can be used for:

- Web servers
- Application servers
- APIs
- Development environments
- Batch processing
- Self-managed databases
- CI/CD workloads

# 03. S3 - Storage

## What is S3?

**Amazon Simple Storage Service (S3)** is an object storage service.

S3 stores data as objects inside buckets.

Architecture:

```text
S3
 |
 +---- Bucket
        |
        +---- Object
        +---- Object
        +---- Object
```

---

# Buckets

A bucket is a logical container for objects.

Example:

```text
my-application-data
```

Bucket names must follow Amazon S3 naming requirements and are globally unique within the S3 namespace.

---

# Objects

An object contains:

- Data
- Key
- Metadata

Example:

```text
Bucket
 |
 +---- images/logo.png
 +---- documents/report.pdf
 +---- data/users.json
```

---

# Storage Classes

S3 provides multiple storage classes for different access patterns.

Examples include:

- S3 Standard
- S3 Intelligent-Tiering
- S3 Standard-IA
- S3 One Zone-IA
- S3 Glacier Instant Retrieval
- S3 Glacier Flexible Retrieval
- S3 Glacier Deep Archive

Storage class selection depends on:

- Access frequency
- Retrieval requirements
- Cost
- Data retention requirements

---

# Versioning

S3 Versioning keeps multiple versions of an object.

For example:

```text
report.pdf
   |
   +---- Version 1
   +---- Version 2
   +---- Version 3
```

Versioning can help recover from accidental deletion or overwriting.

---

# Lifecycle Policies

Lifecycle policies automatically transition or delete objects based on defined rules.

Example:

```text
S3 Standard
     |
     | After a period
     v
Infrequent Access
     |
     | After another period
     v
Glacier
```

Lifecycle policies can help reduce storage costs.

---

# Encryption

S3 supports encryption to protect stored data.

Encryption options include:

- Server-side encryption
- AWS managed keys
- Customer managed AWS KMS keys
- Client-side encryption

Sensitive data should be protected using appropriate encryption and access controls.

---

# Bucket Policies

Bucket policies are resource-based policies that control access to an S3 bucket.

They can specify:

- Who can access the bucket
- Which actions are allowed
- Which resources are affected
- Conditions for access

S3 access should be configured carefully to avoid accidental public exposure.

---

# Common S3 Use Cases

S3 is commonly used for:

- Backups
- Static website assets
- Log storage
- Data lakes
- Media files
- Documents
- Application artifacts
- Archive storage

# 04. VPC - Networking

## What is VPC?

**Amazon Virtual Private Cloud (VPC)** provides a logically isolated network in AWS.

A VPC allows users to control:

- IP address ranges
- Subnets
- Routing
- Network security
- Internet connectivity

Architecture:

```text
AWS
 |
 +---- VPC
       |
       +---- Public Subnet
       |
       +---- Private Subnet
       |
       +---- Route Tables
       |
       +---- Internet Gateway
       |
       +---- NAT Gateway
```

---

# CIDR

CIDR defines the IP address range of a network.

Example:

```text
10.0.0.0/16
```

This can be used as the CIDR block for a VPC.

A smaller subnet might use:

```text
10.0.1.0/24
```

---

# Subnets

Subnets divide a VPC into smaller network segments.

They are associated with an Availability Zone.

Common types:

- Public subnet
- Private subnet

---

# Route Tables

Route tables determine where network traffic is sent.

Example public subnet route:

```text
0.0.0.0/0
      |
      v
Internet Gateway
```

A private subnet may instead route internet-bound traffic through a NAT Gateway.

---

# Internet Gateway

An Internet Gateway allows communication between a VPC and the internet when routing and addressing are appropriately configured.

Typical public subnet architecture:

```text
Internet
    |
    v
Internet Gateway
    |
    v
Route Table
    |
    v
Public Subnet
    |
    v
EC2
```

---

# NAT Gateway

A NAT Gateway allows resources in a private subnet to initiate outbound connections to the internet without directly accepting unsolicited inbound internet connections.

Example:

```text
Private EC2
    |
    v
Private Route Table
    |
    v
NAT Gateway
    |
    v
Internet Gateway
    |
    v
Internet
```

---

# Security Groups

Security Groups provide stateful network access control for resources such as EC2 instances.

They control allowed inbound and outbound traffic.

---

# Network ACLs

Network Access Control Lists (NACLs) provide an additional layer of subnet-level traffic control.

Unlike Security Groups, NACLs are associated with subnets and use numbered rules.

---

# Public vs Private Subnet

## Public Subnet

A subnet is considered public when its routing configuration provides a path to an Internet Gateway, and resources have appropriate public addressing if internet communication is required.

Common resources:

- Public load balancers
- Bastion hosts
- Public-facing servers

## Private Subnet

Private subnets do not provide a direct route from resources to the Internet Gateway for inbound internet traffic.

Common resources:

- Databases
- Internal application servers
- Backend services

---

# 05. DynamoDB & RDS - Database Services

# DynamoDB

## What is DynamoDB?

Amazon DynamoDB is a fully managed **NoSQL database service**.

It is designed for applications requiring low-latency and highly scalable data access.

---

# Tables

DynamoDB stores data in tables.

Example:

```text
Users
 |
 +---- User 1
 +---- User 2
 +---- User 3
```

---

# Items

An item is an individual record in a DynamoDB table.

Example:

```json
{
  "userId": "101",
  "name": "Monika",
  "department": "IT"
}
```

---

# Attributes

Attributes are the individual data elements of an item.

Example:

```text
userId
name
department
email
```

DynamoDB is flexible about the attributes stored in items, subject to the table's key schema and application requirements.

---

# Partition Key

The partition key determines how DynamoDB distributes data and identifies items for access.

Example:

```text
Partition Key:
userId
```

A well-designed partition key helps distribute workload effectively.

---

# Sort Key

A sort key can be used together with a partition key to create a composite primary key.

Example:

```text
Partition Key: customerId
Sort Key: orderId
```

This allows multiple related items to exist under the same partition key.

---

# DynamoDB Use Cases

Common use cases include:

- Serverless applications
- High-scale web applications
- Gaming applications
- IoT applications
- Session management
- Real-time applications
- Applications requiring low-latency access

---

# RDS

## What is RDS?

**Amazon Relational Database Service (RDS)** is a managed relational database service.

It simplifies tasks such as:

- Database provisioning
- Backups
- Patching
- Monitoring
- Scaling
- High availability configuration

---

# Supported Database Engines

Amazon RDS supports several relational database engines, including:

- Amazon Aurora
- PostgreSQL
- MySQL
- MariaDB
- Oracle
- Microsoft SQL Server

---

# DB Instances

An RDS DB instance provides the compute and storage environment for a relational database.

Configuration can include:

- Instance class
- Storage
- Database engine
- Network configuration
- Security settings

---

# RDS Security

RDS security can involve:

- VPC configuration
- Security Groups
- IAM integration where supported
- Encryption
- Database authentication
- Network isolation

A database should generally not be directly exposed to the public internet unless there is a specific, justified requirement.

---

# Backups

RDS supports automated backups and snapshots.

Backups can help recover databases after:

- Accidental deletion
- Data corruption
- Application errors
- Infrastructure problems

---

# Multi-AZ

Multi-AZ deployments provide high availability by maintaining a standby database instance in another Availability Zone.

Simplified architecture:

```text
Availability Zone A
       |
   Primary DB
       |
       | Replication
       |
Availability Zone B
       |
   Standby DB
```

The standby is primarily intended for high availability and failover rather than ordinary read scaling.

---

# Read Replicas

Read replicas are copies of a database used primarily to scale read workloads.

Example:

```text
             Primary DB
                 |
        +--------+--------+
        |                 |
        v                 v
    Read Replica 1    Read Replica 2
```

Applications can send read traffic to replicas while writes continue to use the primary database.

---

# RDS Use Cases

RDS is commonly used for:

- Web applications
- Enterprise applications
- E-commerce systems
- Transactional applications
- Business applications
- Applications requiring relational databases

---

# DynamoDB vs RDS

| Feature | DynamoDB | RDS |
|---|---|---|
| Database type | NoSQL | Relational |
| Data model | Key-value/document | Tables and relationships |
| Schema | Flexible | Structured |
| SQL | No traditional SQL interface | SQL |
| Scaling | Designed for horizontal scale | Depends on engine/configuration |
| Transactions | Supported | Supported |
| Managed service | Yes | Yes |
| Common use | High-scale low-latency apps | Relational applications |

# Important Security Notes

AWS credentials should **never** be written directly into Terraform files.

Do not use:

```hcl
provider "aws" {
  access_key = "MY_ACCESS_KEY"
  secret_key = "MY_SECRET_KEY"
}
```

Instead, configure AWS credentials using an appropriate AWS authentication mechanism, such as the AWS CLI credential configuration or an IAM role where applicable.

Check AWS CLI configuration:

```bash
aws configure
```

Verify the current identity:

```bash
aws sts get-caller-identity
```

Do not commit:

```text
AWS access keys
AWS secret keys
Private keys
Terraform state containing sensitive information
```

```text
IAM       → Identity & Governance
EC2       → Compute
S3        → Object Storage
VPC       → Networking
DynamoDB  → NoSQL Database
RDS       → Relational Database
```

Together, these concepts provide a foundation for building and managing **cloud infrastructure using Terraform and AWS**.
